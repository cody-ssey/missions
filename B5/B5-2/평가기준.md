# B5-2 평가기준

2026-09-30, 사용자가 제공한 [미션 평가 체크리스트](https://mission-checklist-ten.vercel.app/)의 Chrome 상세 화면에서 옮겼습니다. 공식 학습 사이트 원문과의 일치 여부는 별도로 확인하지 않았습니다. 화면의 문항 순서와 문구를 보존하며, 체크 상태는 변경하지 않았습니다.

1. INIT <user_name> 실행 후 main 브랜치/HEAD/현재 사용자 설정이 정상적으로 초기화되어 있는가?
2. BRANCH <name> 생성 후 SWITCH <name> 로 전환되며, 이후 COMMIT 이 해당 브랜치에 반영되는가?
3. LOG 가 "부모 커밋이 자식 커밋보다 먼저" 출력되도록 동작하는가?
4. PATH <a> <b> 가 경로가 있으면 최단 경로를, 없으면 No path 를 출력하는가?
5. ANCESTORS <hash> 가 모든 조상을 빠짐없이 출력하는가?
6. SEARCH <keyword> / SEARCH --author=<name> / LOG --sort-by=date|author 가 요구사항대로 동작하는가?
7. 커밋 저장소/브랜치/HEAD/사용자 정보를 어떤 구조로 분리했고, 각 책임을 설명할 수 있는가?
8. 커밋 hash로 빠르게 조회하기 위해 어떤 키-값 구조를 사용했고, 중복/충돌을 어떻게 방지했는지 설명할 수 있는가?
9. 커밋이 추가될 때 역색인(author/keyword)을 어떤 시점에, 어떤 방식으로 갱신하도록 설계했는지 설명할 수 있는가?
10. LOG, PATH, ANCESTORS 에서 사용하는 그래프 탐색 로직을 어떻게 재사용 가능하게 구성했는지 설명할 수 있는가?
11. 주요 함수/클래스에 docstring/주석을 어떤 기준으로 작성했는지 설명할 수 있는가?
12. 커밋 그래프가 왜 DAG여야 하는지, 사이클이 생기면 어떤 문제가 발생하는지 설명할 수 있는가?
13. LOG 에서 "부모가 먼저" 조건을 만족시키기 위해 어떤 접근(예: 위상 정렬 성격의 출력)을 적용했는지 설명할 수 있는가?
14. PATH 에서 최단 경로를 찾기 위해 어떤 알고리즘(예: BFS)을 선택했고, 간선을 무방향으로 정의한 이유를 설명할 수 있는가?
15. 정렬 알고리즘의 평균/최악 시간복잡도와 안정 정렬 여부를 설명할 수 있는가?
16. 역색인이 순회 검색보다 빠른 이유를, 자료구조/시간복잡도 관점에서 설명할 수 있는가?
17. 커밋 수가 10배 늘어났을 때 병목이 될 지점을 예측하고, 개선 방향(자료구조/알고리즘)을 설명할 수 있는가?
18. PATH 의 간선 정의를 "부모 방향만 허용"으로 바꾸면 결과가 어떻게 달라지고, 구현은 무엇을 바꿔야 하는지 설명할 수 있는가?
19. LOG --sort-by=author 요구사항이 "부모-자식 선후도 유지"로 강화된다면, 어떤 전략으로 해결할지 설명할 수 있는가?
20. 해시 생성 방식을 카운터 기반 ↔ 난수 기반으로 바꿀 때 테스트/재현성/디버깅에 미치는 영향을 설명할 수 있는가?
